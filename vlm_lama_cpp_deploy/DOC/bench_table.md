# Qwen2.5-VL-3B 性能展示表（Jetson Orin 8GB · llama.cpp · Q4_K_M）

> 数据来源：`data1.log`（bench_auto.py 自动化基准，唯一提问绕过文本缓存）
> 纯文本为稳态 4 轮平均（第 2~5 轮，剔除冷启动）；图片为真实图片 prefill 轮（455 输入 token）

## 主表：15W / 25W × 纯文本 / 图片理解

| 任务类型 | 功耗模式 | Prefill 输入处理<br>(tok/s) | TTFT 首 token 延迟<br>(ms) | Decode 生成速度<br>(tok/s) |
|---------|:-------:|:------------------------:|:------------------------:|:------------------------:|
| 纯文本 | 15W | 233.4 | 116 | 15.3 |
| 纯文本 | **25W** | **372.0** | **72** | **23.9** |
| 图片理解 (768px) | 15W | 180.2 | 2525 | 15.2 |
| 图片理解 (768px) | **25W** | **268.6** | **1694** | **23.5** |

## 功耗模式带来的提升

| 指标 | 纯文本 15W→25W | 图片理解 15W→25W |
|------|:---:|:---:|
| Prefill (tok/s) | 233.4 → 372.0（**+59%**） | 180.2 → 268.6（**+49%**） |
| TTFT (ms) | 116 → 72（**-38%**） | 2525 → 1694（**-33%**） |
| Decode (tok/s) | 15.3 → 23.9（**+56%**） | 15.2 → 23.5（**+55%**） |

## 关键结论

1. **25W 模式全面提升约 5~6 成**：无论纯文本还是图片，prefill +49~59%、decode +55~56%、TTFT -33~38%，性能敏感场景应锁定 25W
2. **图片开销集中在输入阶段**：图片 prefill 耗时（1694~2525ms）约为纯文本（72~116ms）的 **15~22 倍**，因为 455 个输入 token 中约 428 个是图片 token，需跑视觉编码器
3. **生成速度不受图片影响**：decode 速度纯文本与图片基本一致（15.2~15.3 / 23.5~23.9），生成阶段不涉及视觉编码
4. **图片缓存收益显著**：同图第二次请求 TTFT 从 1694ms 降至 73ms（约 **23 倍加速**），重复图片场景（监控、视频抽帧）受益极大
